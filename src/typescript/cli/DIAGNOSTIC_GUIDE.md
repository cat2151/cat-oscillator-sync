# TypeScript CLI Mouse Frequency Update Diagnostic Guide

## 問題の概要

TypeScript CLI版で、マウス位置を変更したときの周波数への変更が、10秒に1回程度しか発生しない問題があります。この問題を診断するための3つの独立したテストスクリプトを用意しました。

## 目標

せめて1秒に10回程度（10Hz以上）の周波数変更を実現する。

## 診断スクリプトの使用方法

### セットアップ

1. プロジェクトのTypeScript CLIディレクトリに移動:
```powershell
cd src/typescript/cli
```

2. 依存パッケージをインストール（まだの場合）:
```powershell
npm install
```

3. TypeScriptをビルド:
```powershell
npm run build
```

### テスト1: マウスキャプチャテスト

マウス位置の取得が正常に動作するかをテストします。

**実行:**
```powershell
npm run diag:mouse
```

または

```powershell
node dist/diagnostics/test-mouse-capture.js
```

**手順:**
1. スクリプトを実行すると、2秒後にテストが開始されます
2. 5秒間、マウスを画面上で動かしてください
3. テスト終了後、結果が表示されます

**期待される結果:**
- マウス位置の変化が検出される
- 変化検出率が10Hz以上
- ポーリングレートが約125Hz

**問題の兆候:**
- マウス位置の変化が全く検出されない → robotjsの問題
- 変化検出率が非常に低い（<1Hz） → マウスキャプチャに問題

### テスト2: 周波数スイープテスト

オーディオシステムが高頻度で周波数を変更できるかをテストします。

**実行:**
```powershell
npm run diag:freq
```

または

```powershell
node dist/diagnostics/test-frequency-sweep.js
```

**手順:**
1. スクリプトを実行すると、2秒後にテストが開始されます
2. 1秒間、440Hzから1760Hzまで滑らかに上昇する音が聞こえます
3. テスト終了後、結果が表示されます

**期待される結果:**
- 滑らかに上昇する音が聞こえる
- 周波数更新レートが100Hz以上
- タイミングジッタが小さい

**問題の兆候:**
- 更新レートが10Hz未満 → オーディオシステムに問題
- 音が途切れる → バッファリングの問題

### テスト3: マウス制御オーディオテスト

マウス入力とオーディオ出力の統合をテストします。

**実行:**
```powershell
npm run diag:audio
```

または

```powershell
node dist/diagnostics/test-mouse-audio.js
```

**手順:**
1. スクリプトを実行すると、2秒後にテストが開始されます
2. 5秒間、マウスを左右に動かしてください
   - 左に動かすと低い音（220Hz）
   - 右に動かすと高い音（1760Hz）
3. テスト終了後、結果が表示されます

**期待される結果:**
- マウスの動きに応じて音の高さが変わる
- 周波数変更レートが10Hz以上
- マウスの動きに対して滑らかに反応する

**問題の兆候:**
- 周波数変更が全く検出されない → 統合部分に問題
- 変更レートが1Hz未満 → これが報告されている問題

### テスト4: メインプログラム診断版

通常のメインプログラムをエラーログ付きで実行します。

**実行:**
```powershell
npm run diag:main
```

または

```powershell
node dist/diagnostics/main-diagnostic.js
```

**オプション（スムーズ版）:**
```powershell
node dist/diagnostics/main-diagnostic.js smooth
```

**手順:**
1. スクリプトを実行すると、通常版と同じように音が出ます
2. マウスを動かして音を制御してください
3. 画面にリアルタイムで以下の情報が表示されます：
   - マスター/スレーブ周波数
   - ポーリング成功率
   - 周波数更新レート
   - エラー回数
4. Ctrl+Cで終了すると、詳細な診断情報が表示されます

**期待される結果:**
- 通常のメインプログラムと同じように動作する
- 成功率が90%以上
- 周波数更新レートが10Hz以上（マウスを適度に動かした場合）

**問題の兆候:**
- 成功率が50%未満 → robotjsに重大な問題
- 成功率は高いが更新レートが低い → マウスの動きが少ないか他の問題
- エラーメッセージが頻繁に表示される → robotjsの権限やインストールに問題

## 診断フローチャート

```
Step 1: マウスキャプチャテストを実行
│
├─ ✅ 変化検出率 ≥ 10Hz → マウスキャプチャは正常
│                         Step 2へ
│
└─ ❌ 変化検出率 < 10Hz → マウスキャプチャに問題あり
                          - robotjsの動作確認
                          - 管理者権限で実行
                          - セキュリティソフトの確認

Step 2: 周波数スイープテストを実行
│
├─ ✅ 更新レート ≥ 100Hz → オーディオシステムは正常
│                          Step 3へ
│
└─ ❌ 更新レート < 10Hz → オーディオシステムに問題あり
                          - speakerパッケージの確認
                          - バッファサイズの調整
                          - バックプレッシャー処理の確認

Step 3: マウス制御オーディオテストを実行
│
├─ ✅ 変更レート ≥ 10Hz → 統合も正常
│                         Step 4へ
│
└─ ❌ 変更レート < 10Hz → 統合部分に問題あり
                          - ポーリングループの確認
                          - setIntervalの精度確認
                          - 周波数更新ロジックの確認

Step 4: メインプログラム診断版を実行
│
├─ ✅ 成功率 ≥ 90%, 変更レート ≥ 10Hz → 問題なし
│                                      通常版で問題が発生する場合は
│                                      hard syncアルゴリズムの影響
│
└─ ❌ 成功率 < 90% or 変更レート < 10Hz → 
      ├─ 成功率が低い場合 → robotjsの問題
      │                      - 管理者権限で実行
      │                      - セキュリティソフトを確認
      │                      - robotjsを再インストール
      │
      └─ 成功率は高いが変更レートが低い場合
                           → メインプログラムのロジックに問題
                             - hard syncの処理負荷
                             - ポーリングループの最適化が必要
```

## 次のステップ

### すべてのテストが成功する場合

診断スクリプトは正常に動作するが、メインプログラムで問題が発生している場合：

1. **hard syncアルゴリズムの影響を調査**
   - 2つのオシレータ（マスター/スレーブ）の相互作用
   - 位相リセットの頻度

2. **メインプログラムのポーリングループを確認**
   - `src/main.ts`の90-115行目
   - `setInterval`のコールバックの実行時間

3. **周波数更新のロジックを見直す**
   - `SimpleSynth`または`SmoothSynth`の`setMasterFrequency`と`setSlaveFrequency`

### 特定の部分に問題がある場合

**マウスキャプチャに問題:**
- robotjsの代替ライブラリを検討
- Windowsネイティブのマウスフックを使用
- ポーリングレートを下げる（125Hz → 60Hz）

**オーディオシステムに問題:**
- バッファサイズを増やす（レイテンシが増加するトレードオフ）
- 異なるオーディオライブラリを試す
- バックプレッシャー処理を改善

**統合部分に問題:**
- ポーリングループの最適化
- 周波数変化の閾値を調整
- 不要な処理を削減

## トラブルシューティング

### ビルドできない

```powershell
# node_modulesを削除して再インストール
Remove-Item -Recurse -Force node_modules
Remove-Item package-lock.json
npm install
npm run build
```

### 管理者権限が必要な場合

PowerShellを管理者権限で開いて実行:
```powershell
# 右クリック → 管理者として実行
cd C:\path\to\cat-oscillator-sync\src\typescript\cli
npm run diag:mouse
```

### Visual Studio Build Toolsが必要な場合

```powershell
winget install --id Microsoft.VisualStudio.2022.BuildTools --override "--wait --passive --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```

## 参考情報

- マウスポーリングレート: 通常125Hz（ゲーミングマウスは1000Hz+）
- オーディオサンプルレート: 48000Hz
- バッファサイズ: 384フレーム（8ms @ 48kHz）
- 目標周波数変更レート: ≥10Hz（100ms間隔以下）
- setIntervalの精度: Windowsでは通常10-16ms程度

1. 各テストスクリプトの出力結果（テキストコピー）
2. 上記の「結果の記録」セクションの情報
3. 問題の発生状況（常に発生 / 時々発生）
4. 使用しているマウスの種類とポーリングレート（わかれば）
