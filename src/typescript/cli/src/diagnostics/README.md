# 診断スクリプト (Diagnostic Scripts)

このディレクトリには、TypeScript CLI版のマウス位置と周波数変更の問題を診断するためのスクリプトが含まれています。

## 目的

メインプログラムでマウス位置を変更したときの周波数への変更が10秒に1回程度しか発生しない問題を診断するため、以下の3つの独立したテストスクリプトを用意しました：

1. **マウスキャプチャのテスト** - マウス位置が125Hzで正しく取得できるかをテスト
2. **周波数変更のテスト** - オーディオシステムが125Hzで周波数を変更できるかをテスト
3. **統合テスト** - マウスとオーディオの統合が正しく動作するかをテスト

## 前提条件

- Windows 10 または Windows 11
- Node.js v20.0.0 以降
- プロジェクトがビルド済み (`npm run build` を実行済み)

## スクリプトの説明

### 1. test-mouse-capture.ts

マウス位置の取得が125Hzで正しく動作するかをテストします。

**テスト内容:**
- 5秒間、8ms間隔でマウス位置をポーリング
- マウス位置の変化を記録
- 変化検出率、タイミング分析を表示

**実行方法:**
```powershell
cd src/typescript/cli
node dist/diagnostics/test-mouse-capture.js
```

**期待される動作:**
- テスト中にマウスを動かすと、位置変化が検出される
- 125Hz程度のポーリングレートが達成される
- マウスを適度に動かせば、1秒あたり10回以上の変化が検出される

**診断ポイント:**
- マウス位置の変化が全く検出されない → robotjsの問題または権限の問題
- 変化検出率が非常に低い → マウスの動きが遅すぎるか、ポーリングに問題がある
- ポーリングレートが125Hzより大幅に低い → setIntervalの精度に問題がある

### 2. test-frequency-sweep.ts

オーディオシステムが125Hzで周波数を変更できるかをテストします。

**テスト内容:**
- シンプルなサイン波オシレータを使用
- 1秒間で440Hzから1760Hzまで周波数をスイープ
- 125回に分けて周波数を変更（8ms間隔）
- 実際の更新レート、タイミングジッタを分析

**実行方法:**
```powershell
cd src/typescript/cli
node dist/diagnostics/test-frequency-sweep.js
```

**期待される動作:**
- 滑らかに上昇する音が聞こえる
- 125回の周波数更新が約1秒で完了
- 更新レートが120-130Hz程度

**診断ポイント:**
- 更新レートが10Hz未満 → オーディオシステムまたはsetIntervalに問題がある
- 更新レートが100Hz以上 → オーディオシステムは正常に動作している
- 音が途切れる → オーディオバッファの問題

### 3. test-mouse-audio.ts

マウス入力とオーディオ出力の統合テストを行います。

**テスト内容:**
- マウスのX座標を周波数にマッピング（220Hz〜1760Hz）
- 8ms間隔でマウス位置をチェックし、周波数を更新
- 5秒間のテスト
- 周波数変更の検出率、タイミングを分析

**実行方法:**
```powershell
cd src/typescript/cli
node dist/diagnostics/test-mouse-audio.js
```

**期待される動作:**
- マウスを左右に動かすと音の高さが変わる
- 適度にマウスを動かせば、1秒あたり10回以上の周波数変更が検出される
- マウスの動きに対して滑らかに周波数が変化する

**診断ポイント:**
- 周波数変更が全く検出されない → マウスキャプチャまたは統合部分に問題
- 変更レートが10Hz未満 → 統合部分のパフォーマンスに問題
- 変更レートが10Hz以上 → 統合は正常に動作している

### 4. main-diagnostic.ts

メインプログラムの診断版。エラーログ付きで実行します。

**テスト内容:**
- 通常のメインプログラムと同じ機能
- マウスキャプチャのエラーをログに記録
- ポーリング成功率、周波数更新レートを表示
- Ctrl+Cで終了時に詳細な診断情報を表示

**実行方法:**
```powershell
cd src/typescript/cli
npm run diag:main
```

または

```powershell
node dist/diagnostics/main-diagnostic.js
```

**期待される動作:**
- 通常のメインプログラムと同じように音が出る
- マウスエラーが発生した場合、コンソールに表示される
- リアルタイムで成功率と更新レートが表示される

**診断ポイント:**
- エラー率が高い（>10%） → robotjsに問題がある
- エラー率が低いが更新レートも低い → 他の原因がある
- エラーがないが更新レートが低い → マウスの動きが少ないか、他の問題がある

## 診断フローチャート

```
1. test-mouse-capture を実行
   ↓
   変化検出率が低い？
   ↓ Yes                    ↓ No
   マウスキャプチャに問題   マウスキャプチャは正常
   
2. test-frequency-sweep を実行
   ↓
   更新レートが低い？
   ↓ Yes                    ↓ No
   オーディオシステムに問題 オーディオシステムは正常
   
3. test-mouse-audio を実行
   ↓
   変更レートが低い？
   ↓ Yes                    ↓ No
   統合部分に問題           統合も正常に動作
```

## トラブルシューティング

### マウス位置が取得できない

**問題:** `Error reading mouse position` のようなエラーが出る

**解決方法:**
1. PowerShellまたはコマンドプロンプトを管理者権限で実行
2. セキュリティソフトがrobotjsをブロックしていないか確認

### ビルドエラー

**問題:** TypeScriptのコンパイルエラー

**解決方法:**
```powershell
cd src/typescript/cli
npm run build
```

### 音が出ない

**問題:** 診断スクリプトで音が出ない

**解決方法:**
1. Windowsの音量設定を確認
2. 既定のオーディオデバイスが正しく設定されているか確認
3. 他のアプリケーションでオーディオが動作するか確認

## 結果の解釈

各スクリプトは実行後に診断結果を表示します：

- ✅ = テスト成功、問題なし
- ⚠️ = 警告、許容範囲だが最適ではない
- ❌ = エラー、問題あり

### 良好な結果の例

```
test-mouse-capture:
  ✅ Mouse capture is working well!
  ✅ Change rate is above 10 Hz (target met!)

test-frequency-sweep:
  ✅ Frequency update rate is excellent!
  Achieved 124.50 Hz (target: 125 Hz)

test-mouse-audio:
  ✅ Frequency change rate meets the target!
  Achieved 15.60 Hz (target: ≥10 Hz)
```

### 問題がある結果の例

```
test-mouse-capture:
  ⚠️ Very few position changes detected.
  
test-frequency-sweep:
  ❌ Frequency update rate is too low!
  Achieved 2.35 Hz (target: 125 Hz)
  
test-mouse-audio:
  ❌ Frequency change rate is very low!
  Achieved 0.80 Hz (target: ≥10 Hz)
```

## 次のステップ

診断結果に基づいて：

1. **マウスキャプチャに問題がある場合:**
   - robotjsの設定を確認
   - 権限の問題を調査
   - 代替のマウス入力ライブラリを検討

2. **オーディオシステムに問題がある場合:**
   - speakerパッケージの設定を確認
   - バッファサイズを調整
   - バックプレッシャー処理を確認

3. **統合部分に問題がある場合:**
   - メインプログラムのポーリングループを確認
   - setIntervalの精度を調査
   - 周波数更新のロジックを見直す

4. **すべてのテストが成功する場合:**
   - メインプログラム特有の問題を調査
   - hard syncアルゴリズムの影響を確認
   - マスター/スレーブ2つのオシレータの相互作用を確認

## 参考情報

- マウスポーリングレート: 通常は125Hz（8ms間隔）
- オーディオサンプルレート: 48000Hz
- バッファサイズ: 384フレーム（8ms分）
- 目標周波数変更レート: ≥10Hz（100ms間隔以下）
